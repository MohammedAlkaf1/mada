# مدى · منصة التدريب والتعلّم

منصة لإدارة التدريب تُباع للجهات باشتراك: شركات، معاهد تدريب، وجهات تعليمية. كل جهة تحصل على مساحة مستقلة باسمها وشعارها ولونها، ترفع فيها محتواها، وتسند الدورات لمتدربيها، وتتابع الإكمال والتأخر، وتصدر شهادات إتمام يمكن التحقق منها. المنصة لا توفر محتوى جاهزًا.

المرجع الوظيفي: وثيقة `Training_Platform_SRS_AR_v0.1` (أرقام المتطلبات FR وBR وNFR مذكورة في الكود حيث تُطبق).

الاسم «مدى» مؤقت. يتغير من مكان واحد: `PRODUCT_NAME_AR` و`PRODUCT_NAME_EN` في البيئة، و`brand` في `src/i18n/dictionary.ts`.

## التشغيل من الصفر

يتطلب Node 22 أو أحدث. قاعدة البيانات PostgreSQL مدمجة للتطوير، فلا حاجة لتثبيت شيء آخر.

```bash
npm install
npm run setup            # ينشئ .env بأسرار عشوائية
npm run db:start         # PostgreSQL محلي على 127.0.0.1:55433 (اتركه يعمل)
npx prisma generate
npm run db:migrate
npm run db:seed          # جهة تجريبية كاملة
npm run dev              # http://127.0.0.1:3100
```

`npm run db:seed -- --reset` يمسح قاعدة التطوير ويعيد البذر.

## حسابات تجريبية

كلمة المرور لكل الحسابات `Demo@12345`. شاشة الدخول تعرض الحسابات وتملأ رمز التحقق تلقائيًا ما دام `DEMO_LOGIN=1` وخارج الإنتاج.

| الحساب | الدور |
|---|---|
| `admin@mada.test` | مسؤول الجهة، ومشغّل المنصة أيضًا |
| `trainer@mada.test` | مدرب، يرى الدورات المسندة إليه فقط |
| `learner@mada.test` | متدرب، لديه دورة قيد التعلم ودورة لم تبدأ وأخرى مكتملة بشهادة |

الجهة التجريبية «نخلة للتجزئة» فيها 39 مستخدمًا وأربع مجموعات وخمس دورات، منها دورة نموذجية كاملة «مهارات الإشراف للقادة الجدد» بثلاث وحدات وثلاثة فيديوهات مسجلة داخل المنصة وملف PDF واختبارات من كل الأنواع واختبار نهائي، وإجابات مكتوبة تنتظر التصحيح. تُسجَّل الفيديوهات مرة واحدة عند أول بذر في data/demo-videos، ومحاولات اختبار وشهادات موزعة على الشهرين الماضيين، وشهادة ملغاة واحدة.

### خارج هذه النسخة

الواجهة الإنجليزية موجودة لكن المرجع الأساسي عربي. لا يوجد SCORM ولا xAPI ولا دخول موحد ولا بث مباشر ولا تطبيق جوال، وهذا مطابق للوثيقة. تخزين الملفات محلي على وحدة تخزين الخادم (`FILES_DIR`)، والتخزين الخارجي المتوافق مع S3 للملفات لم يُنفذ بعد (النسخ الاحتياطية لقاعدة البيانات تدعمه).

## الفحص

```bash
npm run typecheck
npm test                 # 61 اختبار وحدة لقواعد التقدم والتصحيح والنشر والاستيراد والشهادات
npm run check:lms        # فحص متصفح شامل لرحلة المسؤول والمتدرب والعزل (يحتاج db:start وdev وdb:seed)
npm run check:site       # الموقع العام
npm run check:operator   # لوحة المشغّل
```

`check:lms` يطابق سيناريوهات القبول: بناء دورة ونشرها، قفل النسخة، الإسناد دون تكرار، الرسوب ثم النجاح، الشهادة والتحقق والإلغاء، عزل جهة أخرى، منع المتدرب من أوامر الإدارة، التصدير، الاستيراد، وعرض الجوال 390 بكسل. ينشئ بياناته ويحذفها بعد الانتهاء.

## المهام الخلفية

```bash
npm run mail:worker      # يرسل البريد من صندوق الصادر (بلا SMTP يكتب الرسائل إلى data/mail)
npm run scheduler        # كل ما يلي في عملية واحدة
```

| المهمة | التكرار | ما تفعله |
|---|---|---|
| `scan:files` | كل دقيقة | يفحص الملفات المعلقة عبر ClamAV |
| `reminders` | كل ساعة | تذكير الموعد وتنبيه التأخر، وتصحيح المحاولات المنتهي وقتها |
| `housekeeping` | يوميًا | إنهاء العضويات المؤقتة، حذف ملفات التصدير المنتهية، تطبيق الاحتفاظ |
| `billing:cycle` | يوميًا | التجارب والتجديد والتحصيل والإيقاف |
| `backup` | يوميًا | نسخة قاعدة البيانات، ونسخة خارجية إن ضُبط S3 |

## وحدة المشغّل

لوحة المشغّل على `/ar/operator` لمن لديه صلاحية المشغّل وتحقق بخطوتين. نفس العمليات من الطرفية:

```bash
npm run operator -- create <slug> "<الاسم>" "<Name>" admin@example.org "اسم المسؤول" [basic|growth|enterprise]
npm run operator -- list | suspend | resume | close | export | purge | grant | revoke | operators
```

الجهة التي ينشئها المشغّل تبدأ تجربة 14 يومًا على الباقة المختارة ويُدعى مسؤولها بالبريد.

## البنية

- كل الكتابة عبر `POST /api/command` إلى `src/lib/commands.ts`، ومنه إلى `course-commands.ts` (التأليف والإسناد) و`learning-commands.ts` (التعلم والاختبار والشهادات).
- القواعد النقية في `src/lib/domain.ts` بلا قاعدة بيانات، فتُختبر مباشرة وتستخدمها الواجهة لشرح القرار نفسه.
- `settle()` في `src/lib/command-kit.ts` يعيد حساب التسجيل من سجلاته ويصدر الشهادة مرة واحدة، ويُستدعى بعد كل تقدم.
- القراءة في `src/lib/queries.ts`، دالة لكل شاشة مقيدة بالجهة والدور. مفاتيح الإجابات لا تُقرأ إلا في استعلامات فريق العمل.
- الملفات: `PUT /api/files` يرفع بالبث دون تحميل الملف في الذاكرة، ويقرأ النوع من البايتات، ويفحص، ويحسب الحصة. `GET` يخدم بنطاقات البايت للفيديو بعد التحقق من الحق.
- الشهادة: `src/lib/certificate-document.ts` ثم `renderPdf` عبر متصفح لأن تشكيل العربية في مكتبات PDF ضعيف. صفحة التحقق `/c/<token>`.

## النشر

صورتان من `Dockerfile`: `app` للتطبيق و`worker` للمهام والترحيلات ووحدة المشغّل. `docker-compose.yml` يشغّل الحزمة على خادم واحد.

```bash
cp .env.example .env          # واملأ القيم المعلّمة (مطلوب)
docker compose up -d --build
curl -s http://127.0.0.1:3000/api/health
```

وحدة التخزين `app-data` تحمل ملفات الدروس ونسخ قاعدة البيانات ومشتركة بين التطبيق والمجدول. انسخها احتياطيًا على مستوى الخادم مع `db-data`. إن كان أمام التطبيق Nginx فاجعل `client_max_body_size` لا يقل عن 1100m لرفع الفيديو.

ClamAV اختياري: `docker compose --profile scan up -d` مع `CLAMAV_HOST=clamav`. بدونه تبقى الملفات معلقة في الإنتاج ولا تُنشر دروسها، بحكم التصميم.

لم تُبنَ الصور على هذا الجهاز لأن Docker غير مثبت عليه.

## قبل أول عميل حقيقي

1. حسم الاسم التجاري. «مدى» هو أيضًا اسم شبكة المدفوعات الوطنية في المملكة، وهذا تعارض يستحق مراجعة قبل الإطلاق.
2. الاستضافة وبلدها (D-04)، والنطاق وشهادة TLS، وقيم `APP_URL` و`AUTH_URL`.
3. مزود بريد وتجربة رسالة دعوة حقيقية، ومفاتيح Moyasar الحية.
4. ClamAV في الإنتاج، ونسخة احتياطية مجدولة لقاعدة البيانات ومجلد الملفات، وتمرين استعادة.
5. مراجعة نظامية لشروط الاستخدام وسياسة الخصوصية، واختبار أداء لسعة NFR-01 واختبار إتاحة بقارئ شاشة.
